# Karabakh Atlas - Dirchalish

Karabakh Atlas is a map website project for exploring Karabakh and its
cities through an interactive, visual interface. It's split into a
backend (a REST API serving region/city data) and a frontend (a
Leaflet-based map UI that renders that data).

## Running locally

**Backend:**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 seed_data.py
python3 -m api.v1.app
```

By default this uses a local JSON file for storage — no database setup
needed. See [Environment variables](#environment-variables) below to run
against PostgreSQL instead.

**Frontend** (in a second terminal):

```bash
cd frontend
python3 -m http.server 8000
```

Then open `http://localhost:8000` in a browser. The API listens on
`http://localhost:5000` by default.

## Environment variables

Copy `.env.example` to `.env` and adjust as needed (never commit a real
`.env`). Everything is optional except when noted:

| Variable | Purpose |
| --- | --- |
| `KBA_TYPE_STORAGE` | `file` (default) or `db` (PostgreSQL) |
| `DATABASE_URL` | Full Postgres connection string; takes priority over the `KBA_DB_*` vars below. Most hosts inject this automatically. |
| `KBA_DB_USER`, `KBA_DB_PWD`, `KBA_DB_HOST`, `KBA_DB_NAME` | Used when `KBA_TYPE_STORAGE=db` and `DATABASE_URL` isn't set |
| `KBA_AUTO_SEED` | `true` to seed starter regions/cities on boot if missing — useful on hosts without shell access to run `seed_data.py` manually |
| `KBA_API_KEY` | If set, POST/PUT/DELETE require a matching `X-API-Key` header. Unset = open writes (fine for local dev, not for a public deploy) |
| `KBA_API_HOST`, `KBA_API_PORT` | Flask dev server bind address (`python3 -m api.v1.app` only; ignored by gunicorn) |

To run the backend against a local Postgres instead of the JSON file:

```bash
sudo -u postgres psql -f setup_postgres_dev.sql
export KBA_TYPE_STORAGE=db KBA_DB_USER=kba_dev KBA_DB_PWD=kba_dev_pwd \
       KBA_DB_HOST=localhost KBA_DB_NAME=kba_dev_db
python3 seed_data.py && python3 -m api.v1.app
```

## Deployment

`render.yaml` deploys the API, the static frontend, and a free
PostgreSQL database together as a Render Blueprint:

1. Push this repo to GitHub (already done if you're reading this from
   there).
2. In the Render dashboard: **New +** → **Blueprint** → select this
   repo. Render reads `render.yaml` and provisions all three services.
3. Once the `karabakh-atlas-api` service is live, copy its URL and set
   it in `frontend/config.js` (`window.KBA_API_BASE`), then redeploy the
   frontend service — the two are on different subdomains, so the
   frontend needs to know where the API lives.
4. The API's `KBA_API_KEY` is auto-generated by the blueprint; find it
   in the `karabakh-atlas-api` service's environment variables and use
   it in the app's "Manage" panel to make edits from the live site.

If Render's Blueprint schema has changed since this was written, the
same three services (a Python web service for the API, a static site
for `frontend/`, and a free Postgres database) can be created by hand
from the dashboard using the settings in `render.yaml` as a reference.
